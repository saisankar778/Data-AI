# Fixtures

All PBIP fixtures are generated by `python fixtures/generate.py`: a small retail model with `Sales`, `Product`, `Customer` and `Calendar` tables (plus `Targets` in `retail-issues`).

> **Verified 2026-10-27:** Power BI Desktop (Oct 2026) opened `retail-report` with all tables. Each fixture now has `Retail.pbip` and a report (blank for clean/issues). Don't open these copies in Desktop directly, because Desktop writes files: use `datawright sample <name> <folder>`, which also copies `fixtures/data/*.csv` and points the model at them.

| Fixture | What it is | Expected |
|---|---|---|
| `pbip/retail-clean` | A model that follows every rule: descriptions everywhere, keys hidden and marked, a marked date table, a `DataFolder` parameter, typed Power Query steps | Health 100, no findings |
| `pbip/retail-issues` | The same model with planted problems (below) | Exactly the findings in `evals/datasets/audit-rules-v1.yaml` |
| `pbip/retail-report` | `retail-clean` plus a PBIR report (`Retail.Report`) whose visuals use every visible field except measure [Order Lines] and column Customer[Segment] | One `unused-measure` and one `unused-column` finding |
| `pbix/Revenue Opportunities.pbix` | A real Microsoft sample (MIT, see `NOTICE`) with a PBIR report inside | Used to test the `.pbix` and report readers |

Planted in `retail-issues`: measures without descriptions (11), `/` instead of DIVIDE, IFERROR, a measure that only returns another, two identical measures, a qualified measure reference, an unqualified column reference, a measure name with a trailing space, a measure without a format string, a floating-point price, visible and summarised keys, an unmarked date table with auto date/time on, an unsorted month column, a city column without a data category, a bidirectional and an unused inactive relationship, unused hidden columns and a hidden measure, an unrelated table, and hard-coded local paths in untyped Power Query sources.

All files use LF line endings and tab indentation. `.gitattributes` keeps Git from converting them, because tests compare bytes.
